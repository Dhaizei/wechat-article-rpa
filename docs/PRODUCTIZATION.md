# 公众号采集器产品化路线

本项目当前定位为“单机、已登录微信账号下的公众号文章采集器”。采集过程会操作微信窗口，因此一台电脑同一时刻只应运行一个任务。

## 已具备的产品能力

- 启动前检查：确认微信主窗口、“搜一搜”窗口、屏幕和缩放环境。
- 自恢复入口：缺少“搜一搜”时，控制台可尝试从微信主窗口打开它。
- 可选采集策略：今天、昨天、今天和昨天；仅转发数或全部互动数。
- 运行时进度：账号位置、当前账号、文章数和阶段均由采集器结构化事件驱动。
- 任务可追溯：每次启动都保存实际参数、环境检查、输出目录、进度摘要和失败样本；控制台重启后未完成任务会明确标记为中断。
- 数据幂等：文章 URL 标准化后用于查找/去重；已有正文不覆盖，互动数据追加为历史快照。

## 本次发布验收

1. 手动任务使用页面当前选择；“按已保存计划测试”使用已保存定时参数。
2. 前置检查不通过时，不启动 RPA 子进程，同时生成一条“前置条件不足”的任务记录。
3. 任务结束、停止或控制台重启后，历史状态不能被旧子进程覆盖。
4. 控制台能看到最近任务摘要；发生账号采集失败时能看到账号名、错误原因和分类。
5. 每次修改至少运行：

   ```powershell
   D:\work_software\Anaconda\python.exe -m unittest discover -s tests -v
   D:\work_software\Anaconda\python.exe -m py_compile rpa_control_panel.py article_ingest.py wechat_visual_rpa.py
   node --check web\app.js
   ```

## 下一阶段优先级

### P0：长期运行可靠性

- 失败账号队列：把失败账号和失败类型持久化，支持在控制台中单独重试。
- 任务恢复策略：控制台启动时识别残留采集进程，提供“终止残留进程”或“重新开始”的明确选择。
- MongoDB 运行审计：为每个任务写入 run ID，便于文章数据和本地运行记录相互追溯。
- 外网/局域网发布保护：若监听非 `127.0.0.1`，必须启用密码或反向代理认证，禁止裸露控制接口。

### P1：可运营性

- 账号目录：展示账号可用状态、别名、最近成功时间和最近失败原因。
- 任务详情页：展示完整失败列表、导出文件、开始/结束时间和按账号统计。
- 完成通知：仅在完成、异常或失败账号超过阈值时发送飞书摘要。
- 数据质量：展示 URL、标题、正文、发布时间、转发数的缺失率与重复率。

### P2：工程化

- 将窗口编排、账号搜索、文章采集和 MongoDB 写入拆成独立模块。
- 扩充离线测试：窗口状态机、日志事件、MongoDB 更新策略和控制台 API。
- 引入 CI：语法检查、单元测试、依赖漏洞扫描和发布包校验。

## 运行边界

- 微信客户端、鼠标和键盘在任务执行时归采集器独占；人工操作会降低稳定性。
- 公众号页面布局、登录状态与微信版本变化会影响识别。错误应优先通过任务诊断归类，再决定是自动恢复、账号别名修正还是人工处理。
- MongoDB 中 `publishDate` 采用公众号页面显示的北京时间，避免筛选“今天/昨天”时发生时区偏移。
