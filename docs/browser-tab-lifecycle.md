# 采集标签的归属与清理

采集使用搜索页、当前公众号主页、当前文章页三类页面。文章处理后关闭本次新开的文章页；账号处理后关闭本次新开的主页，返回搜索页。微信复用原有标签时，只切回原页面；同标签导航使用后退。

微信将另一个公众号主页替换成新账号时，使用 `reused_profile_tab` 返回路径。只有旧主页已经登记归属，才把归属转移给新主页并在结束后关闭；复用用户原有主页不会获得关闭权。存在额外不明页面变化时仍保留页面。

因发布时间超出范围而跳过的文章，也会复核前后链接并提供标题、账号的验证结果，用于非标准文章的安全清理。`profile_return_preserved` 表示返回了搜索页但保留了归属不明的页面，不等于清理成功。

本程序确认新增页面后，将窗口、文档 key、标题、角色与微信进程 PID、创建时间写入 `output/owned-browser-tabs.json`。确认关闭后删除对应归属记录。每个采集进程第一次使用该浏览器时，先尝试清理上轮明确登记的遗留文章和主页。搜索页从不登记为可关闭页面。

以下页面会保留：任务之前原有的页面、没有归属记录的历史页面、微信重启后的旧记录、标题或文档身份变化的页面。异常退出发生在创建页面与登记之间时，也可能留下无法确认归属的页面。程序不根据标题猜测所有权，因此不承诺整个浏览器始终只有三个标签。

清理失败会记录错误并停止当前操作；不要直接删除归属文件来解决标签过多的问题，这会丢失后续安全清理所需的证据。记录损坏时停止自动清理，不把损坏内容当作有效归属。

当前变更已通过离线测试；真实暂停、恢复和跨任务清理还需下一轮采集验证。

自定义标签兼容：对于微信暴露的 `TabStrip/Tab` 控件，读取其 RuntimeId 和新鲜坐标，不伪造选中状态。单个搜索标签可建立初始对应关系；唯一新增目标标签通过直接点击该实体的标题区并复核当前文档建立对应关系，后续由文档身份及仍存在的标签编号定位。已有多个未绑定标签、标签复用或身份异常仍使用兼容遍历。2026-09-15 本机两篇实际采集确认公众号及文章均产生 `created_direct` / `restore_direct`，两篇成功、无失败；不代表所有微信版本均已通过。

导航检查缓存按微信进程会话和公众号隔离。每次读取当前页面及标签编号、标题和选中状态；只有标签列表完全一致且当前文档身份一致时，检查点才复用已有遍历结果。缓存命中记录为 `browser_navigation` 的 `inventory_cached` 阶段。

唯一新增目标标签、全部原标签仍保持不变且目标页面身份通过时，打开公众号和文章使用 `created_direct` 路径，不切换其他标签。关闭前重新读取这些证据；关闭后必须确认标签列表精确恢复基线，再按原标签 RuntimeId 直接选择并复核原页面身份，成功记录 `restore_direct`。无法读取唯一选中状态、复用旧标签、同页跳转或出现额外变化时，仍回退完整遍历。直接选择不受支持时可遍历寻找原页面，但不会重复关闭。关闭结果异常时保留归属记录并停止。
